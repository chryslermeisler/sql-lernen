1Primärschlüssel und Fremdschlüssel

Primärschlüssel

Ein Primärschlüssel ist ein Attribut (oder eine Gruppe von Attributen), dessen Werte jeden Datensatz eindeutig identifizieren. Kein Wert darf in der Tabelle zweimal vorkommen. Im Tabellenschema wird er unterstrichen.

Oft nimmt man einen künstlichen Schlüssel – eine fortlaufende Nummer wie KundenID oder eine Kennnummer wie die ISBN. Warum? Natürliche Merkmale wie der Name sind irgendwann nicht mehr eindeutig: Es gibt viele „Anna Müller“.

Fremdschlüssel

Ein Fremdschlüssel ist eine Spalte, die Werte des Primärschlüssels einer anderen Tabelle enthält. Damit „zeigt“ ein Datensatz auf einen Datensatz der anderen Tabelle – so werden Tabellen miteinander verknüpft. Im Tabellenschema wird er gestrichelt unterstrichen.

Fahre mit der Maus über einen Wert der Spalte Klassenleiter (oder tippe darauf):

Merke Schulklasse(Klasse, Zimmer, Klassenleiter)
Lehrkraft(Kürzel, Name, Vorname, F1, F2)
Klassenleiter enthält nur Werte von Kürzel → Klassenleiter ist ein Fremdschlüssel.
Für einen Join (Verbund) gilt immer: <Tabelle1.Primärschlüssel> = <Tabelle2.Fremdschlüssel>, hier: WHERE Klassenleiter = Kuerzel
  • Ein Primärschlüsselwert kommt genau einmal vor.
  • Ein Fremdschlüsselwert darf mehrmals vorkommen (Frau Herberger leitet zwei Klassen).
  • Jeder Fremdschlüsselwert muss in der anderen Tabelle als Primärschlüssel existieren – sonst zeigt er „ins Leere“.
So formulierst du es in der Kurzarbeit (je 2 Punkte):
Primärschlüssel: „Ein Attribut oder eine Kombination von Attributen, deren Werte jeden Datensatz einer Tabelle eindeutig identifizieren. Kein Wert darf doppelt vorkommen.“
Fremdschlüssel: „Ein Attribut, das Werte des Primärschlüssels einer anderen Tabelle enthält. Es verknüpft die beiden Tabellen miteinander, damit man z. B. bei Abfragen zusammengehörige Datensätze verbinden kann (Verbundbedingung).“

2Kreuzprodukt und Verbundbedingung

Wir wollen wissen: Welcher Kunde hat welche Bestellung aufgegeben? Die Namen stehen in Kunde, die Bestellungen in Bestellung. Also schreiben wir beide Tabellen hinter FROM. Aber Vorsicht – schau, was passiert:

Merke Bei der Verwendung mehrerer Tabellen in einer Abfrage erhält man zunächst das Kreuzprodukt: jede Zeile der einen Tabelle wird mit jeder Zeile der anderen kombiniert (4 Kunden × 6 Bestellungen = 24 Zeilen). Die meisten Kombinationen sind Unsinn.
Mit der Verbundbedingung (Primärschlüssel = Fremdschlüssel) behält man nur die Zeilen, die wirklich zusammengehören. Kreuzprodukt + Verbundbedingung = Verbund (Join). 
SELECT Vorname, Nachname, BestellID
FROM   Kunde, Bestellung
WHERE  Kunde.KundenID = Bestellung.KundenID

Tabelle.Spalte – wann nötig?

Die Spalte KundenID gibt es in beiden Tabellen. Schreibst du nur KundenID, weiß die Datenbank nicht, welche gemeint ist (Fehlermeldung „mehrdeutig“). Darum schreibt man Kunde.KundenID bzw. Bestellung.KundenID. Bei eindeutigen Namen wie Vorname darf man den Tabellennamen weglassen – man darf ihn aber immer dazuschreiben.

Probier es selbst: Lösche die WHERE-Zeile und führe die Abfrage erneut aus. Wie viele Zeilen kommen heraus?

SELECT Vorname, Nachname, BestellID FROM Kunde, Bestellung WHERE Kunde.KundenID = Bestellung.KundenID
Andere Schreibweise (zur Info): Statt der Bedingung im WHERE-Teil kann man auch FROM Kunde JOIN Bestellung ON Kunde.KundenID = Bestellung.KundenID schreiben. Das Ergebnis ist gleich. Im Unterricht wird die WHERE-Schreibweise verwendet – bleib in der Kurzarbeit dabei.

3Das Abfrage-Rezept

Mit diesen vier Schritten löst du jede Aufgabe über mehrere Tabellen. Beispiel: „Welche Buchtitel hat Anna Müller bestellt?“

  1. Was soll ausgegeben werden? → Titel (steht in Buch). Das kommt hinter SELECT.
  2. Welche Tabellen brauche ich? Alle Tabellen, aus denen ich Spalten ausgebe oder in Bedingungen benutze (Vorname, Nachname → Kunde) – und alle Tabellen „auf dem Weg dazwischen“. Kunde und Buch hängen nicht direkt zusammen, sondern über Bestellung. → FROM Kunde, Bestellung, Buch
  3. Verbundbedingungen: Für jede Verbindung „Primärschlüssel = Fremdschlüssel“. Bei n Tabellen braucht man n−1 Verbundbedingungen, hier also 2.
  4. Weitere Bedingungen, Sortierung: Vorname = 'Anna' AND Nachname = 'Müller', eventuell ORDER BY, DISTINCT.
SELECT Titel
FROM   Kunde, Bestellung, Buch
WHERE  Kunde.KundenID = Bestellung.KundenID     -- Verbund Kunde–Bestellung
  AND  Bestellung.BuchID = Buch.BuchID          -- Verbund Bestellung–Buch
  AND  Vorname = 'Anna' AND Nachname = 'Müller' -- eigentliche Bedingung
SELECT Titel FROM Kunde, Bestellung, Buch WHERE Kunde.KundenID = Bestellung.KundenID AND Bestellung.BuchID = Buch.BuchID AND Vorname = 'Anna' AND Nachname = 'Müller'

Abkürzungen für Tabellen (Aliasse)

Lange Tabellennamen kann man hinter FROM abkürzen. Das spart Schreibarbeit – so ist es auch in den Musterlösungen:

SELECT Name, Vorname
FROM   Buch b, Buch_zu_Autor ba, Autor a
WHERE  b.BuchNr = ba.BuchNr AND ba.AutorNr = a.AutorNr
  AND  Titel = 'Natur und Technik - Informatik'

Braucht man eine Tabelle zweimal (z. B. Start- und Zielflughafen), muss man ihr zwei Namen geben: FROM Flughafen AS start, Flughafen AS ziel.

Doppelte Zeilen: DISTINCT

Durch einen Verbund kommt dieselbe Angabe oft mehrfach vor. „In welchen Orten wohnen Kunden, die etwas bestellt haben?“ – Anna aus Nürnberg hat zweimal bestellt, Nürnberg stünde also doppelt da. SELECT DISTINCT Ort entfernt doppelte Zeilen.

SELECT DISTINCT Ort FROM Kunde, Bestellung WHERE Kunde.KundenID = Bestellung.KundenID
Spalten hinter SELECT dürfen auch aus mehreren Tabellen kommen, z. B. SELECT Nachname, Titel, Anzahl. Wichtig ist nur, dass alle diese Tabellen im FROM stehen.

4Rechnen über mehrere Tabellen

Aggregatfunktionen funktionieren genauso über verbundene Tabellen: Zuerst wird der Verbund gebildet und gefiltert, dann wird gerechnet.

FunktionBedeutung
COUNT(*)Anzahl der Zeilen
SUM(Spalte)Summe
AVG(Spalte)Durchschnitt
MIN(Spalte) / MAX(Spalte)kleinster / größter Wert

Beispiel (AB5 c): Durchschnittspreis der beim Verlag Meise erschienenen Bücher:

SELECT AVG(Preis) FROM Buch b, Verlag v WHERE b.VerlagNr = v.VerlagNr AND Kurzname = 'Meise'

Pro Gruppe rechnen: GROUP BY

„Wie viele Bestellungen hat jeder Kunde?“ – „jeder“ bzw. „pro“ heißt: GROUP BY. Jede Spalte hinter SELECT, die nicht in einer Aggregatfunktion steht, muss auch hinter GROUP BY stehen.

SELECT Nachname, COUNT(*) AS Bestellungen, SUM(Anzahl) AS Buecher FROM Kunde, Bestellung WHERE Kunde.KundenID = Bestellung.KundenID GROUP BY Nachname

Mit HAVING filtert man Gruppen (z. B. HAVING COUNT(*) > 1), mit WHERE einzelne Zeilen vor dem Gruppieren.

Wer hat den Höchstwert? Unterabfrage!

Typische Falle (AB1 Aufgabe 10/11): „Wie lange dauert das längste Lied der Katzen?“ ist leicht – SELECT MAX(Laenge). Aber „Wie heißt das längste Lied?“ geht nicht mit SELECT LiedTitel, MAX(Laenge). Man braucht eine Unterabfrage, die zuerst den Höchstwert berechnet:

SELECT LiedTitel FROM Lied, CD WHERE Lied.CDTitel = CD.CDTitel AND Bandname = 'Katzen' AND Laenge = (SELECT MAX(Laenge) FROM Lied, CD WHERE Lied.CDTitel = CD.CDTitel AND Bandname = 'Katzen')
Wichtig: Aggregatfunktionen dürfen nie direkt im WHERE-Teil stehen. WHERE Preis = MAX(Preis) ist falsch → WHERE Preis = (SELECT MAX(Preis) FROM Buch)

5Redundanz, Konsistenz und Anomalien

Ein Versandhandel speichert alles in einer Tabelle. Was fällt auf?

Merke Redundanz = unnötige Mehrfachspeicherung von Daten (redundant gespeicherte Daten).
Konsistent = die Datenbank ist ohne Widersprüche, die Daten sind korrekt. Widersprüchliche Daten = inkonsistent.
Fehler, die beim Ändern redundanter Daten entstehen, heißen Anomalien:
  • Änderungs-/Update-Anomalie: Beim Aktualisieren werden Datensätze vergessen → Datenbank inkonsistent.
  • Lösch-/Delete-Anomalie: Beim Löschen gehen Informationen für immer verloren, die man noch braucht.
  • Einfüge-/Insert-Anomalie: Neue Daten lassen sich nicht eintragen, weil Teile des Primärschlüssels fehlen.

Die Lösung: Aufteilen in mehrere Tabellen

Redundanzen entstehen, wenn Informationen, die zu verschiedenen Klassen gehören, in einer Tabelle stehen. Man teilt die Tabelle so auf, dass jede Tabelle nur inhaltlich zusammengehörige Informationen enthält – und verbindet sie über Fremdschlüssel:

Kunde(KdNr, Name, Vorname, Adresse, Telefon)
Artikel(ArtNr, Artikel, Preis)
Bestellung(KdNr, ArtNr, BDatum, Anzahl)

Jetzt steht Müllers Adresse nur noch einmal in der Datenbank. Änderungen passieren an genau einer Stelle, Kunden bleiben erhalten, wenn ihre Bestellungen gelöscht werden, und neue Artikel kann man jederzeit eintragen.

6Beziehungen und Kardinalitäten

Im Klassendiagramm zeichnet man die Klassen als Kästen und die Beziehung als Linie mit Beschriftung in beide Leserichtungen. Die Kardinalitäten geben an, mit wie vielen Objekten der anderen Klasse ein Objekt in Beziehung stehen kann.

So liest man es – die Kardinalität steht immer bei der Klasse, zu der man hinliest:

  • „Ein Buch erscheint bei genau einem Verlag.“ (die 1 steht beim Verlag)
  • „Ein Verlag gibt 0 bis n (beliebig viele) Bücher heraus.“ (das n steht beim Buch)
KardinalitätEin Objekt der einen Klasse steht mit … der anderen Klasse in Beziehung
1genau einem Objekt
nkeinem, einem oder mehreren Objekten
0..1keinem oder einem Objekt
1..neinem oder mehreren Objekten

Die drei Beziehungstypen

TypBeispielGelesen
1:1Mitarbeiter – DienstwagenEin Mitarbeiter hat höchstens einen Dienstwagen; ein Dienstwagen ist höchstens einem Mitarbeiter zugewiesen.
1:nVerlag – Buch, Messstation – MesswertEin Verlag hat viele Bücher; jedes Buch hat genau einen Verlag.
n:mNutzer – Gruppe, Buch – AutorEin Nutzer ist in vielen Gruppen; jede Gruppe hat viele Nutzer.
Trick zum Bestimmen: Stell dir für beide Richtungen die Frage „Kann ein … mehrere … haben?“. Zweimal „nein“ → 1:1. Einmal „ja“ → 1:n. Zweimal „ja“ → n:m.

71:n- und 1:1-Beziehungen umsetzen

Vom Klassendiagramm zum Tabellenschema

Legt man einfach zwei Tabellen an, weiß niemand, von welcher Messstation ein Messwert stammt. Die Beziehung muss im Tabellenschema sichtbar werden: Man fügt in Messwert eine Spalte station_id ein, die den Primärschlüssel der Messstation enthält – den Fremdschlüssel.

Messwert(id, temperatur, zeitstempel, station_id)
Messstation(id, ort, betreiber)

Merke Bei einer 1:n-Beziehung wird der Primärschlüssel der „1-Seite“ in der Tabelle der „n-Seite“ als Fremdschlüssel hinzugefügt.
Bei einer 1:1-Beziehung kann der Fremdschlüssel in jeder der beiden Tabellen eingefügt werden.

Warum nicht andersherum?

Würde man messwert_id in die Messstation schreiben, hätte jede Station Platz für nur einen Messwert. Genau dieser Fehler passierte im Webshop-Beispiel (AB4 Aufgabe 2): Kunde(kundennummer, name, e-mail, nachricht_id) – schickt ein Kunde zwei Nachrichten, wird die erste überschrieben.

Eselsbrücke: Das „Viele“ zeigt auf das „Eine“. Jeder Messwert weiß, zu welcher Station er gehört – nicht umgekehrt. Genauso: jedes Buch kennt seinen Verlag (VerlagNr steht in buch).

Abfrage über die 1:n-Beziehung

SELECT ort, temperatur, zeitstempel FROM Messstation, Messwert WHERE Messstation.id = Messwert.station_id ORDER BY ort

Sonderfall 1:1 (Mitarbeiter – Dienstwagen)

Der Fremdschlüssel darf in beide Tabellen. Sinnvoll ist meist die Tabelle, bei der er fast immer belegt ist: Haben nur wenige Mitarbeiter einen Dienstwagen, kommt personalnummer als Fremdschlüssel in Dienstwagen (sonst wären bei den meisten Mitarbeitern leere Felder). Bei 1:1 kann man beide Klassen auch in einer Tabelle zusammenfassen.

8n:m-Beziehungen umsetzen

Jeder Nutzer kann in mehreren Gruppen sein, jede Gruppe hat mehrere Nutzer. Ein einfacher Fremdschlüssel reicht nicht:

Nutzer – so geht es NICHT
vornamenametelefon_nrgruppen_id
JimPanse+49176223341 | 42
AnnaNass+49159765431 | 2 | 42

„Ich kann nicht nach den Mitgliedern der Gruppe 2 suchen – die Einträge sind nicht atomar. Und „1 | 42“ passt nicht in eine Spalte vom Typ ZAHL.“

Die Lösung: eine Beziehungstabelle

In der Beziehungstabelle stehen die Primärschlüssel der in Beziehung stehenden Datensätze. Jede Zeile ordnet einen Nutzer einer Gruppe zu.

Nutzer(vorname, name, telefon_nr)
Nutzer_zu_Gruppe(telefon_nr, gruppen_id)
Gruppe(id, name, gegründet)

Merke Eine n:m-Beziehung wird mit einer zusätzlichen Beziehungstabelle umgesetzt. Sie enthält die Primärschlüssel beider Tabellen als Fremdschlüssel.
Der Primärschlüssel der Beziehungstabelle ist die Kombination der beiden Fremdschlüssel.
Aus einer n:m-Beziehung werden so zwei 1:n-Beziehungen.

Abfragen über n:m

Für eine Abfrage muss zwischen jeder Tabelle, in der sich eine Information befindet, und der Beziehungstabelle ein Join erstellt werden. In welchen Gruppen ist Jim Panse Mitglied?

SELECT Gruppe.name FROM Nutzer, Nutzer_zu_Gruppe, Gruppe WHERE Nutzer.name = 'Panse' AND vorname = 'Jim' AND Nutzer.telefon_nr = Nutzer_zu_Gruppe.telefon_nr AND gruppen_id = id

Die Beziehungstabelle muss immer mit ins FROM – auch wenn man keine Spalte von ihr ausgibt. Noch ein Beispiel (AB5 Aufgabe 4c): Für welche Workshops hat sich Johannes eingeschrieben?

SELECT Workshop.name FROM Schueler, Schueler_zu_Workshop, Workshop WHERE Schueler.name = 'Johannes' AND Schueler.id = schueler_id AND Workshop.id = workshop_id

Datenbanksysteme Tabellen & Datentypen SQL-Grundlagen Aggregatfunktionen

Rückblick: Datenbanksysteme

Zwischen der Anwendersoftware (z. B. Browser, LibreOffice Base) und der Datenbasis (den gespeicherten Daten) vermittelt eine Software: das Datenbankmanagementsystem (DBMS). Es nimmt Anfragen entgegen, prüft sie und greift auf die Daten zu.

DBMS + Datenbasis + Metadaten + Anwendersoftware zusammen nennt man Datenbanksystem (DBS).

Relationale Datenbanken

  • Aus jeder Klasse wird eine Tabelle.
  • Aus jedem Attribut wird eine Spalte.
  • Aus jedem Objekt mit seinen Attributwerten (Datensatz) wird eine Zeile.
  • Jeder Attributwert steht in einer Zelle.
  • Es darf keine zwei Zeilen geben, die in allen Attributwerten übereinstimmen.

Der Objektname (z. B. person1) erscheint nicht in der Tabelle.

Rückblick: Tabellen, Datentypen, Schlüssel

TypBezeichnung in Datenbanken
TextTEXT, VARCHAR
ZahlINT, FLOAT, REAL, DOUBLE, DECIMAL
DatumDATE
ZeitTIME
WahrheitswertBOOLEAN (Ja/Nein)

Alle Zellen einer Spalte haben denselben Datentyp.

Tabellenschema

Im Tabellenschema stehen der Tabellenname und alle Spalten mit Typ: 

Mitglied(Name: Text; Vorname: Text; Adresse: Text; Eintritt: Datum; Beitrag: Zahl; gezahlt: Wahrheitswert)

Der Primärschlüssel (hier die Kombination aus Name und Vorname) wird unterstrichen. Weil Namen irgendwann doppelt vorkommen, nimmt man besser einen künstlichen Schlüssel (z. B. MitgliedNr, Personalausweisnummer, ISBN).

Ein Datensatz ist eine Zeile, z. B. (Hopf; Hans; …; 90; WAHR).

Rückblick: SQL-Grundlagen

SQL (Structured Query Language) ist formatfrei, übersichtlich ist aber: Schlüsselwörter groß, jedes in eine neue Zeile. Die Reihenfolge darf nicht verändert werden:

SELECT   Spalte1, Spalte2   -- was ausgeben?
FROM     Tabelle            -- woher?
WHERE    Bedingung          -- welche Zeilen?
GROUP BY Spalte             -- Gruppen bilden
HAVING   Bedingung          -- welche Gruppen?
ORDER BY Spalte [DESC]      -- sortieren

Eine Abfrage ist wie eine Funktion: Eingabe sind Tabellen, Ausgabe ist eine neue Tabelle, die nicht dauerhaft gespeichert wird.

Spickzettel

Schlüssel

Primärschlüssel (unterstrichen): Attribut(e), deren Werte jeden Datensatz eindeutig identifizieren.
Fremdschlüssel (gestrichelt): Attribut, das Primärschlüsselwerte einer anderen Tabelle enthält → verknüpft Tabellen.
Künstlicher Schlüssel: fortlaufende Nummer/ID ohne Bezug zum Objekt.

Abfrage über mehrere Tabellen

SELECT Spalten
FROM   Tab1, Tab2, Tab3
WHERE  Tab1.PS = Tab2.FS
  AND  Tab2.FS = Tab3.PS
  AND  weitere Bedingung
ORDER BY Spalte

Ohne Verbundbedingung → Kreuzprodukt (jede Zeile × jede Zeile).
n Tabellen → n−1 Verbundbedingungen.
Gleicher Spaltenname in 2 Tabellen → Tabelle.Spalte.
Tabellen „auf dem Weg“ und Beziehungstabellen mit ins FROM!

Rezept

  1. Was ausgeben? → SELECT
  2. Welche Tabellen (auch dazwischen)? → FROM
  3. Verbundbedingungen PS = FS
  4. Bedingungen, DISTINCT, ORDER BY

Rechnen

SELECT Ort, COUNT(*), AVG(Preis)
FROM   buch, verlag
WHERE  buch.VerlagNr = verlag.VerlagNr
GROUP BY Ort
HAVING COUNT(*) > 10

„pro / jeder“ → GROUP BY. Nicht aggregierte Spalten im SELECT → auch ins GROUP BY.

Redundanz & Anomalien

Redundanz: unnötige Mehrfachspeicherung. Konsistent: ohne Widersprüche.
Änderungsanomalie: nicht alle Kopien geändert → inkonsistent.
Löschanomalie: Löschen vernichtet noch benötigte Infos.
Einfügeanomalie: Einfügen unmöglich, weil Teil des Primärschlüssels fehlt.
Lösung: Aufteilen in mehrere Tabellen + Fremdschlüssel.

Kardinalitäten

1 genau eins · n keins, eins oder mehrere · 0..1 keins oder eins · 1..n mindestens eins.
Lesen: „Ein Buch erscheint bei genau einem Verlag. Ein Verlag gibt n Bücher heraus.“

Umsetzen ins Tabellenschema

1:n: PS der 1-Seite als FS in die Tabelle der n-Seite.
1:1: FS in eine der beiden Tabellen (oder eine Tabelle).
n:m: Beziehungstabelle mit beiden PS als FS; ihr PS = Kombination beider FS.

Buch(BuchNr, Titel, VerlagNr*)
Verlag(VerlagNr, Kurzname)
Buch_zu_Autor(BuchNr*, AutorNr*)
Autor(AutorNr, Name, Vorname)
* = Fremdschlüssel (gestrichelt)
